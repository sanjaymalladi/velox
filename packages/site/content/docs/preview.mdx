# Preview

`velox preview` starts a local **Velox Studio** session — a browser player wired to your entry file with hot reload.

```bash
velox preview reel.vml
velox preview video.ts
```

## What preview does

- Serves the current composition over HTTP
- Recompiles when the source file changes
- Shows the timeline, playback controls, and frame scrubber
- Matches the same compile path used by `velox render` (WYSIWYG for layout and timing)

Preview does **not** run the final H.264 encoder — use `velox render` for pixel-perfect export and audio mux.

## Workflow

1. Start preview on your entry file.
2. Edit VML or TypeScript; save to refresh.
3. Scrub transitions and caption timing.
4. When satisfied, `velox lint` then `velox render`.

## Keyboard shortcuts

| Key | Action |
|-----|--------|
| Space | Play / pause |
| ← / → | Previous / next frame |
| Shift + ← / → | Jump faster |
| E | Export (when supported in studio) |

## When to use preview vs draft render

| Need | Tool |
|------|------|
| Layout, copy, caption timing | `velox preview` |
| Share a file with stakeholders | `velox render --draft` |
| Final delivery | `velox render` at full quality |

## Troubleshooting

- **Blank canvas** — check lint output; invalid markup may fail compile silently in older builds.
- **Fonts look different** — preview and render share font loading, but system fallbacks can differ; pin webfont assets if needed.
- **Preview won't start** — confirm port is free; try another terminal without stale node processes.
